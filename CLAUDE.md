# mfe-pot-job-bank-mfe

## What this is

The **job search and apply** frontend for the mfe-pot Government of Canada MFE proof-of-technology. Federated as a remote into both `mfe-pot-msca-shell` and `mfe-pot-job-bank-shell`, but built to also work standalone on a real-world Job Bank site outside either shell entirely — that concrete requirement is *why* the platform's "components live in the app, not a separate feature library" pattern exists at all (see the platform repo's CLAUDE.md), and this app was the **original React reference implementation** every other app's own Angular-to-React conversion copied its shape from. Also the first app taken through the whole repo extraction, so its Docker/Helm/CI setup is the template every other app repo's followed.

## What's in this repo

- `apps/job-bank-mfe` — the frontend, federated on port `4203` in local dev. Repo directory, Nx project, federation identity (`federation.config.mjs`'s `name`), Docker image, and Helm chart/release are all named `job-bank-mfe` — the `-mfe` suffix disambiguates this internal federated remote from `mfe-pot-job-bank-shell`'s plain `job-bank` front-door name (see the meta repo's `../CLAUDE.md`). The underlying business-domain naming (Nx `scope:job-bank` tag, `libs/data-access`'s `JobBankApiClient`) deliberately stays un-suffixed — that's domain identity, not hosting identity.
- `apps/job-bank-bff` — job-bank's dedicated BFF (port `3001`), plain Express/TypeScript, routes already carry the `/api` prefix internally (`/api/jobs`, `/api/applications`, `/health` at root) — deliberate, since it's what lets the Ingress path rule below be a plain prefix match with no rewrite. **Not** suffixed `-mfe` — no naming collision to disambiguate, no reason to touch it.
- `apps/job-bank-mfe/src/app/components/*.tsx` — the real component/business logic (`FeatureSearch.tsx`, `FeatureApply.tsx`, `JobApplicationsList.tsx`) — job-bank's whole reason for existing as reusable-outside-the-shell code, not a separate Nx library the way an Angular-era `libs/feature-*` split would have organized it. `libs/data-access` — `JobBankApiClient`.
- `charts/job-bank-mfe` — deploys the frontend+BFF pair as one Helm release; the reference every other app-repo chart was copied from.

Depends on published packages from GitHub Packages: `@tn4consulting/shared-auth`, `shared-auth-server`, `shared-content-client`, `shared-federation-config`, `shared-i18n`, `shared-runtime-config`, `shared-session-cache`, `shared-ui-scds-core` (pinned in `package.json`; keep in sync with `platform-versions.json` in `mfe-pot-platform`). **No `shared-federation-runtime`** — see below.

## Repo-specific things worth knowing

- **`App` (`apps/job-bank-mfe/src/app/App.tsx`) renders a CMS-driven intro block** (`job-bank.intro` key, fetched via `ContentClient` — `content-client.ts`, same pattern as every other app's own `content-client.ts`) above the `FeatureSearch`/`FeatureApply`/`JobApplicationsList` sections, re-fetched via a `useEffect` on cross-remote locale change. `runtime-config.ts`'s `strapiBaseUrl` points at `mfe-pot-platform`'s `charts/strapi` in a real deployment (`http://cms.mfe-pot.local`, browser-to-server, not in-cluster Service DNS). **The feature components' own section headings/table headers/buttons/status text are now CMS-driven too** (`job-bank.search.*`/`job-bank.apply.*`/`job-bank.applications-list.*` keys, batch-fetched via `ContentClient.getPageContents` and the local `use-page-contents.ts` hook) — previously hardcoded English, and `JobApplicationsList.tsx` previously used its own local `useTranslations` hook (removed from `public/assets/i18n/*.json` once migrated) instead of CMS content like every other app's own widgets. No component keeps its own hardcoded fallback text anymore — `createContentClient(strapiBaseUrl, assetBaseUrl)` (`content-client.ts`) always wraps Strapi with a `FallbackContentClient` backed by `public/assets/content-fallback/{en,fr}.json`, so a CMS outage degrades to bilingual fallback content instead of English-only text; see the platform repo's CLAUDE.md "i18n" section for the full mechanism.
- **The CMS-content key namespace (`job-bank.*`) and every business-domain identifier (`JobBankApiClient`, Nx `scope:job-bank` tag, `libs/data-access`) stayed exactly `job-bank`, not `job-bank-mfe`**, when this repo's hosting identity was suffixed — those describe the job-search domain, unrelated to which hostname/federation-name this specific frontend build is reachable at. Only rename them too if the domain concept itself changes, not for a hosting-identity reason.
- **job-bank never consumes a cross-remote widget-loader Context** (it only ever *exposes* one, `./JobApplicationsWidget`), so it has no dependency on `@tn4consulting/shared-federation-runtime` at all — unlike `dashboard`/`employment-life-events`, which both consume widgets a shell mediates.
- **`JobApplicationsList.tsx` is now rendered directly by this app's own `App.tsx`**, after `FeatureApply` — `mfe-pot-dashboard-mfe` used to be the only thing that rendered it (embedded via `./JobApplicationsWidget`, loaded through `useJobApplicationsWidgetLoader()`, host-mediated through `mfe-pot-msca-shell`), but dropped that embed since `docs/msca-screenshots/dashboard.png` has no job-applications tile on the dashboard page; this app's own page is now the one place a citizen actually sees it. The federation expose is untouched (still real, still buildable, in case a future consumer wants it) — `JobApplicationsList.tsx` was already fully self-configuring with no props, so rendering it here needed no changes beyond the import.
- **`federation.config.mjs`'s `exposes` map paths must point at `apps/job-bank-mfe/...`, not the pre-rename `apps/job-bank/...`** — confirmed this is exactly the gotcha the platform repo's CLAUDE.md documents ("`federation.config.mjs`'s `exposes` map needs checking on any app that exposes something beyond its own root component") — a stale path here fails the federation build with `FsPath ... does not exist`, and it's easy to miss since most of a rename touches `project.json`/chart/Docker files, not this map.
- **This repo hit (and fixed) most of the extraction-wide Docker/Jest/tsconfig gotchas first** — see the platform repo's CLAUDE.md ("Monorepo → per-app repos") for the full list (the `@tn4consulting` ESM `transformIgnorePatterns` fix, the npm-auth BuildKit secret mount, the `nx` postinstall hang fix via `pnpm.onlyBuiltDependencies`, the explicit `"types": ["node"]` fix). If a build/test/Docker problem here looks unfamiliar, check that list before assuming it's new.
- **`Chart.yaml`'s library-chart `dependencies` resolve via a sibling-checkout-relative `file://` path** into `../mfe-pot-platform/charts/mfe-frontend-lib` (and `mfe-backend-lib`) — this only works if `mfe-pot-platform` is checked out as an actual sibling at the expected relative path (see `../mfe-pot.code-workspace`). The packaged `.tgz` dependency archives `helm dependency update` generates are gitignored, not committed, since they'd drift stale relative to the source charts.
- **`dashboardBffBaseUrl`-style same-origin pattern**: `runtime-config.ts`'s `jobBankBffBaseUrl` dev default is `http://localhost:3001`, but the chart's `values.yaml` overrides it to `/api` — a same-origin Ingress path rule, not a second hostname, since `job-bank-bff`'s routes already carry that prefix internally.
- **CI** (`.github/workflows/ci.yml`): lint/test/build (including `job-bank-bff`'s separately-run `eslint:lint` target), then builds both images, spins up an ephemeral `kind` cluster, `helm install`s this chart, and curls the Ingress-routed hostname to confirm it serves — the template every other app repo's workflow follows, matching the pattern this repo already set for Docker/Helm. See `README.md` for local install/serve/build/Docker/Helm instructions.
